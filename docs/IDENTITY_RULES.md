# ECDAT Deterministic Identity Rules Specification

## 1. Overview & Objectives

In cryptographic security posture management and quantum risk auditing, scans are run repeatedly across CI/CD pipelines, container registries, and live network targets. If asset and finding identities drift across scans:
- Historical trending and triage state (e.g. accepted risk, false positive, remediation in progress) breaks.
- De-duplication across hybrid discovery tools fails.
- Vulnerability lifecycle metrics become invalid.

ECDAT specifies a **versioned, deterministic, collision-resistant identifier system** governed by mathematical canonicalization.

---

## 2. Identifier Format (URN)

All external entities generated by ECDAT conform to the following URN syntax:

```text
urn:ecdat:<version>:<entity_type>:<tenant_id>:<app_id>:<category_or_type>:<digest>
```

### Components
- `version`: Identity scheme version (`v1`).
- `entity_type`: Entity class: `asset`, `finding`, `evidence`, `relationship`.
- `tenant_id`: URL-safe alphanumeric slug representing the organizational tenant (default: `default`).
- `app_id`: URL-safe alphanumeric slug representing the application, repository, or system (default: `default`).
- `category_or_type`: For assets, the canonical `AssetType` (e.g. `algorithm`, `certificate`, `network_endpoint`, `hardcoded_private_key`, `crypto_library`).
- `digest`: 32-character hexadecimal truncated SHA-256 hash computed over the canonical JSON representation of the entity's immutable identity attributes.

---

## 3. Canonicalization & Collision Prevention (RFC 8785)

### Delimiter-Confusion Defense
Simple delimiter concatenation (e.g. `tenant + ":" + app + ":" + name`) is vulnerable to injection attacks where field boundaries blur (e.g. `tenant="a:b", app="c"` vs `tenant="a", app="b:c"`).

ECDAT eliminates delimiter injection by serializing entity descriptors using **RFC 8785 JSON Canonicalization Scheme (JCS)**:
1. **Sorted Keys**: Object keys are sorted lexicographically by UTF-16 code units.
2. **Deterministic Representation**: Whitespace is stripped, floating point numbers follow IEEE 754 canonical format, and string escaping is normalized.
3. **Cryptographic Hashing**: SHA-256 is computed over the resulting canonical UTF-8 bytes.

---

## 4. Stability Rules & Excluded Volatile Attributes

To guarantee stability across commits and repeated scans:
- **Excluded**: Mutable display names and human labels.
- **Excluded**: Source code line numbers and column offsets (which shift whenever code is added or removed elsewhere in a file).
- **Excluded**: Local absolute file paths (`C:\Users\...` or `/home/...`). Only normalized relative workspace paths (e.g. `src/auth/jwt.js`) are used.
- **Excluded**: Scan runtime timestamps, execution UUIDs, and database row IDs.

---

## 5. Authorization & Multi-Tenancy Protection

Internal database sequence IDs (e.g., PostgreSQL `SERIAL` integers) are strictly internal. Public API endpoints use compound authorization:
- Requests for `/api/v1/assets/:assetId` verify that the asset belongs to the caller's authorized tenant context.
- External IDs are unguessable due to SHA-256 cryptographic digests, preventing IDOR (Insecure Direct Object Reference) enumeration attacks.
